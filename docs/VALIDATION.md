## 实际界面流程

在本机独立测试数据目录，通过实际界面完成空白图标导入、预设应用、自定义保存、CPU 选择、本地模型校验、修片/光影重塑切换、输入列表追加与移除。经典预设仅修改当前照片，三张照片参数同步与撤销均成功，选中范围有明确张数。

光影重塑使用日落金光方案，明确选择 NVIDIA GPU、长边 256、每阶段 10 步、低显存模式。实际完成 256×256 新图生成并加入照片库，再导出 PNG。导出旁车确认 device=cuda、Torch 2.7.1+cu128、原片关联、输入编辑快照和裁切信息。生成输出有明显光色与细节变化；不据此声称身份保真或整体质量已经达到专业修图标准。

浏览器实际检查 1366×768 与 1093×614 CSS 像素可用区域（后者对应较高缩放下的空间压力，不等于全套操作系统 DPI 认证）。未出现横向内容溢出，模块入口、导入、效果对照和整体强度可见，长工具区可滚动。工作区改为中性灰，主要说明不依赖 8～10 像素小字。原尺寸细节仍需看导出，预览长边最多 1600。

检查期间修正了光影工具容器缺失、连续导入覆盖、上传中可提前导出、实际设备显示滞后、预览结束后提示仍称处理中、退出保存期间仍可编辑等问题。界面参照及验收规则见 [INTERFACE.md](INTERFACE.md)。

## 原生单窗口

固定 SDK Microsoft.Web.WebView2 1.0.4314.35；本机 Evergreen Runtime 157.0.4341.46。真实原生进程检查确认 WebView DOM complete、chrome.webview 桥可用、前端保存钩子可调用。保存拒绝时不会退出；异步保存会等待；退出等待期间冻结编辑，失败/取消可恢复。正常退出会停止其所属服务，第二启动器复用旧服务时不会误停旧服务。

原生可见窗口通过可访问性树确认直接承载修片/光影重塑操作页；浏览器中完成布局与图片视觉检查。本机窗口截图 API 曾超时，因此没有把该 API 的失败当作原生应用视觉验证通过。隐藏 WebView 实际启动/退出验证与独立后端生命周期记录均通过。

Profile、cache、crash 和可配置临时目录使用测试指定的 F 盘目录。原生默认大小按当前屏幕工作区限幅。缺少 WebView2 或 VC++ Runtime 时提供微软官方入口，未在全新 Windows 虚拟机验证全部系统前置条件。

## 旧版升级与发行

真实 0.2.0 隔离副本导入测试照片后升级到 0.3.0。解压升级包前后，Data 的 23 个文件 SHA-256 不变；新版启动后 17 个模型、原图和哨兵文件保持，旧照片参数与保护笔刷保留。runtime/AI Python 哈希及 Cache 哨兵不变。新版正常启动与退出代码均为 0。日志和状态默认字段在正常启动时会更新。

Core、AI、单包转发及升级包使用明确白名单，不携带测试照片、用户凭据、编辑状态、缓存或模型权重。生成档案后逐项校验 CRC 并记录 SHA-256。应用源码、构建脚本、依赖来源及许可随包提供。实际解压重启验证结果与发布清单另行保存。

经典 GPU 仅加速合成，人脸分析、修肤和文件压缩仍在 CPU；首次 CUDA 初始化有等待，小图未必更快。8 GB 显卡仍是兼容目标，4070 Ti 12 GB 符合建议但未实测，AMD/Intel GPU 尚未接入。没有完成多用户可用性实验、全套无障碍认证或完整网络抓包。
