# 交互布光：方法、来源与边界

适用于 0.4.0。交互布光取代主界面的生成式流程；0.3.0 及更早的软件包仍采用旧生成界面。实际构建和验收范围见 [VALIDATION.md](VALIDATION.md)。

## 使用方法

导入照片，在“光影重塑”中等待一次照片分析。选择十个布光预设之一，或添加方向光、点光源、聚光灯、柔光箱。画布带编号的控制点可拖动，聚光灯的十字点调整照射目标；选中后也可用方向键微调。右侧调整强度、色温、柔度、角度与距离，最多四盏灯。

作用范围提供“仅主体 · 保留背景”“仅背景 · 保留主体”和“整张照片”，默认仅主体，切换预设会保留当前范围。头发、衣物与身体均属于人物选区；仅背景使用其反向选区。开启“显示作用选区”后，中央画布高亮当前受光区域，便于检查发丝、轮廓和背景覆盖；高亮只作查看，不写入保存或导出照片，原图视窗也不显示高亮。

调灯或修改灯光参数时，选区叠加自动关闭，直接显示实际效果。若所有可见视窗都在看原图，会将一个视窗切换为处理结果。中央状态区显示作用范围、整体强度和是否保留；实际绘制完成后才显示“实时预览”，点击“保留调整”成功后显示“已保留”。整体强度为零、布光关闭或没有有效光源时，明确提示未生效。画布外的光源以带方向箭头的边缘标记显示，拖动标记可直接把光源放到当前画布位置。

分析支持 CPU、自动、NVIDIA GPU。预览优先使用 WebGL2，不可用时降为长边最多 384 像素的 CPU 计算。GPU 预览与深度分析是两个不同阶段；浏览器可能通过软件实现 WebGL2，因此“图形加速预览”不作为指定独立显卡实际参与的证明。

点击“保留调整”写入当前照片的灯光参数和作用范围，不增加照片。可撤销，重启仍保留。放弃调整恢复上次保留的配置。未保留时切图、切模块或导出会先让用户处理草稿；从原生窗口关闭时，未保留草稿会拒绝退出并提示先保留或放弃。正在分析或下载布光模型时，退出检查也会拒绝退出，需先停止任务或等待完成。0.4.0 桌面启动器检查布光任务，并保留前端草稿检查。

本地更新后须关闭所有照影窗口再重新打开。仅再开一个窗口会复用旧后台；界面检测到后台能力不匹配时会明确提示重启，避免将更新未生效误报为没有选择照片。

## 处理路径

1. 原片转正、转换到 sRGB；Depth Anything V2 Small 只运行一次空间分析。缓存键包含原片 SHA-256、固定模型、几何处理版本与选区策略版本；升级策略会生成新缓存键，已保留的旧几何仍可读取，不会静默改写已有布光结果。
2. 深度是相对逆深度。由其梯度近似表面法线；MediaPipe 多类分割的 `1-background` 作为主体概率，10% 以下归零、90% 以上归一，中间区间连续羽化。实测样片的清晰背景仍有约 8.4% 的前景概率，旧 5% 下限会让背景带入微弱布光；当前策略清除这类残留，同时保留边缘的软权重。该阈值不代表发丝已经达到精细抠图质量。
3. 布光底图包含当前修片，但不包含已保存布光。修片在原尺寸计算一次，按照片、修片参数、笔刷、分析及模型版本缓存；准备预览、保留和导出均使用这份底图。缓存每张最多三份，总计以 512 MiB 为清理目标（刚生成的单张超大文件暂时保留）。灯光改变不会再次推理，不会把上一次预览反复叠加。
4. 设主体选区为 `S`，仅主体的作用权重 `M=S`，仅背景为 `M=1-S`，整张照片为 `M=1`。在线性 RGB 中计算：`output = base * (1 + (gain - 1) * strength * M)`；`gain = ambient + 各光源的色温、方向、漫反射与衰减贡献`。方向光无距离衰减，点光按距离衰减，聚光有平滑光锥，柔光箱取中心和四角样本。
5. 禁用、整体强度为零、无有效光源时逐字节返回底图。作用权重为零的像素直接复制：仅主体模式保留 `S=0` 的背景，仅背景模式保留 `S=1` 的主体，羽化边缘按权重过渡。保存后预览及原尺寸导出使用相同公式；导出旁车记录 `scope=subject/background/all` 和对应保留策略。导出为 8-bit sRGB；JPEG 压缩会造成额外像素变化，精确检查使用 PNG。

图形预览最多 1024 像素；高分辨率输出在 CPU 分块计算，并插值估计法线、深度与选区。缩放到 100% 不会凭空得到原尺寸几何细节。

使用过布光的照片，其保留预览采用与交互预览相同的几何采样尺寸及无损 PNG，避免原先 1600 像素 JPEG 预览带来的跳变。原尺寸导出沿用同一修片底图和布光公式；由于采样尺寸不同，将导出重新缩小后仍可能有局部差异，不承诺跨尺寸逐像素一致。WebGL 与 NumPy 的浮点舍入也可能相差一个 8-bit 色阶。

重新打开优先读取上次保留的几何和选区；“重新分析照片”检查当前分析版本并更新需要更新的缓存，同版本仍可复用。更换几何后显示尚未保留，放弃和撤销都会恢复原配置与几何。保存失败会回滚对应版本的参数，不把失败的操作误记为已保留。

## 能力边界

这是单张照片估计几何后的近似布光。原有的阴影、反光、色温混合已经烘焙在照片中，不能保证去除旧阴影、恢复过曝、准确投射新阴影或遮挡。法线不是扫描获得的真实三维表面。发丝、透明物、反射材质、多个交叠人物及强透视可能出现错误；主体选区边缘也可能不准。建议先用低强度并检查面部与轮廓。

主界面不再使用提示词生成整张新照片。旧 IC-Light 服务、模型资料和历史结果仍兼容；其生成行为及许可见 `RELIGHTING.md`，不应把那份历史文档中的限制混同于交互布光。

## 来源与复现

- [Depth Anything V2](https://github.com/DepthAnything/Depth-Anything-V2)：固定官方代码与 Small 权重，完整版本、哈希见 `models/lighting-manifest.json`，Apache-2.0 原文和 vendor 修改记录随源码保留。未引入 transformers 升级；官方 DPT/DINOv2 仅依赖现有 Torch 推理路径。
- [ComfyUI ReLight](https://github.com/EnragedAntelope/comfyui-relight)、[StudioLight](https://github.com/maciejtajber/ComfyUI-StudioLight)：调查了基于几何的交互思路；本轮未复制其代码或模型。
- [LG_Relight](https://github.com/LAOGOU-666/Comfyui-LG_Relight)：作为交互参考；未发现 LICENSE，因此未复制或分发该项目代码。

源码运行依赖既有 core 与 AI 环境。`PORTRAITLAB_AI_PYTHON` 指向独立 AI 解释器；几何模型由界面下载到 `Data/models/lighting/depth_anything_v2_vits.pth`，与扩散模型目录独立。首次准备需要同时有基础人脸／分割模型。无需额外安装 ComfyUI。软件发行不限定盘符；测试所用 F 盘路径是开发环境配置。
