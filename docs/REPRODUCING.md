# 复现与发布检查

## 固定环境

1. 将完整源码放在 `F:\codex` 下，保留 `LICENSE`、`THIRD_PARTY_NOTICES.md` 和 `portraitlab/vendor`。
2. 执行 `setup.ps1 -DownloadModels`。如需固定解释器，添加 `-PythonPath`。本次验证后的全依赖版本记录在 `requirements.lock.txt`；不要把最新版浮动依赖的结果当作相同环境。
3. 核对 `models/manifest.json` 中两个实际模型的期望 SHA-256。下载完成和模型可推理应分别验证；清单中的 downloadable 只表示具备固定公开下载来源。
4. 用 `PORTRAITLAB_WORK` 指定 F 盘运行根目录，或采用默认值：本次发行是任务下的 `work\portraitlab`，普通检出目录是源码下的 `.local`。其下 `runtime` 保存模型、照片和会话数据，`venv`、`temp`、`cache` 分别保存环境、临时文件和依赖／浏览器缓存。`PORTRAITLAB_DATA` 可单独覆盖 `runtime`；所有路径必须在 `F:\codex` 内，研究照片不进入源码发布包。
5. 运行 `Launch.cmd`；需要自动化验证时可用 `Launch.ps1 -NoBrowser`。只连接该次启动的本机端口。

## 本次引擎验证

2026-11-13 使用 MediaPipe 0.10.21、NumPy 1.26.4、OpenCV 4.11.0.86、SciPy 1.15.3，12 项引擎测试通过。另用两张本地样片（正面 1783×2400、侧脸 1920×2560）完成真实模型分析、渲染与关闭；这些样片不随源码分发。stderr 未出现初次试用 MediaPipe 0.10.35 时观察到的 Clearcut 发送失败日志。日志和二进制字符串检查不是网络抓包，不据此作完全零联网保证。

## 验证记录

使用有权处理的照片，记录输入文件 SHA-256、像素尺寸、环境版本、模型 SHA、参数和输出 SHA。至少覆盖正脸、侧脸、低照度、多脸、无脸以及带雀斑／妆容的样片；这些是建议的后续验收场景，不表示本版已全部测过。

检查实际导出文件，而不只看缩略图：零强度／零不透明度、保护区域、批量同步后的逐图参数、无人脸提示、取消或失败任务、同名导出与原图保护。比较画质时固定色彩转换与缩放，区分像素误差、结构变化和主观观感，不用单个模糊 MAE 证明保身份。

运行仓库提供的测试，并把命令、时间、通过／失败数和未测试项写入该次验证记录。安装完成不代表测试通过，单元测试通过也不代表真人修图质量已经验收。

## 源码发布

本次研究源码可在满足 AGPL-3.0-only 条款下发布；不加“仅限非商业”的额外代码限制。公开修改版时保留上游版权、许可证和改动说明；适用的网络交互源码提供要求见 LICENSE 第 13 条。

发布包只包含源码、依赖说明、许可证和预期模型清单。排除 `.local`、虚拟环境、模型权重、上传／导入副本、缓存、预览、导出、个人路径记录和测试照片。`.gitignore` 只是辅助规则，打包前仍须实际检查内容。

对本次源码包计算 SHA-256，记录 RapidRetouch 固定提交、归档 SHA、版本和修改范围。只有真的复跑过的检查才记为通过；模型运行状态与其独立许可核验状态分开记录。
