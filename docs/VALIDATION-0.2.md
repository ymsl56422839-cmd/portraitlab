## 真实 IC-Light 推理

13 个固定模型文件共 3,853,344,390 字节，逐个 SHA-256 核验通过。使用 Torch 2.7.1+cu128、CUDA 12.8；wheel 包含 sm120。

| 路径 | 输出 | 每阶段步数 | 总时间 | CUDA 峰值 allocated / reserved |
|---|---:|---:|---:|---:|
| GPU，方向 left，低显存模式 | 512×768 | 20 | 49.62 s | 2.28 / 2.60 GiB |
| GPU，方向 none，常驻 SDPA | 512×512 | 10 | 30.97 s | 2.62 / 3.21 GiB |
| CPU，方向 left，float32 | 256×256 | 10 | 36.71 s | 0 / 0 |

总时间包括该次导入、模型校验、加载、推理和写入；不是热启动纯采样时间。allocated/reserved 是 PyTorch 分配器统计，不等于整块显卡占用或最低硬件要求。不同 GPU、显存带宽、驱动和图像配置会改变结果。

CPU 仅验证了表中的小图；不据此承诺大图实时。8 GB / 512 低显存是兼容目标，12 GB 是建议配置；尚未在 4070 Ti 12 GB 或 8 GB 实卡上复测。AMD／Intel GPU 加速尚未实现。

生成输出已逐张查看，存在真实光照变化，也存在人物细节、服装与背景变化，不构成身份保真或专业修图质量保证。方向参数不是精确物理光源坐标。

## 实际浏览器流程

通过本机工作台界面完成：

1. 打开 AI 面板，自动识别 CUDA GPU 与显存。
2. 对现有照片提交当前修肤快照，真实运行 IC-Light 双阶段生成。
3. 输出 384×512 新照片并加入照片库，原片继续保留。
4. 从界面导出实际生成尺寸的 PNG。
5. 读取导出 JSON，确认原片关系、请求参数及真实 CUDA 模型元数据完整保留。

生成前对照使用提交时的输入快照，并按模型记录的缩放／中心裁切对齐；不会把另一张缩略图放大当成原尺寸 AI 输出。新增结果初始将经典修肤强度置零，可继续逐项编辑。

## Windows 便携与路径

官方 CPython 3.12.10 x64 嵌入式发行版，发布摘要 SHA-256 校验通过。经典与 AI site-packages 分别复制到独立运行时，不把依赖开发机基础 Python 的虚拟环境直接作为软件包。

已经完成中文目录移动后的独立解释器导入、原生 EXE 启动、照片导入、真实 MediaPipe 预览与带鉴权的正常关闭。中文模型路径、PNG 输出也已验证；中文目录中的嵌入式 AI 解释器完成 256×256 CPU 生成。模型通过字节缓冲区交给 MediaPipe，避免其原生路径处理的兼容问题。

实际文件操作均在开发工作区内完成；程序发行逻辑没有固定盘符限制。尚未在全新 Windows 虚拟机核验所有系统前置条件。Windows 10／11 x64 和 Microsoft Visual C++ x64 运行库为当前发行要求；未覆盖所有浏览器、驱动、旧显卡、杀毒软件策略和网络存储环境。

发行 ZIP 的文件清单、CRC、SHA-256 及最终从 ZIP 重新解压后的检查结果随发布记录保留。公开包排除模型权重、测试照片、用户会话和缓存。
